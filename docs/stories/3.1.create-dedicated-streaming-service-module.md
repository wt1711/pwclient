# Story 3.1: Create a Dedicated Streaming Service Module

## Status

Done

## Story

**As a** developer working on the AI Assistant feature,
**I want** a self-contained streaming service module that manages EventSource connections,
**so that** the complex SSE logic is abstracted away from UI components and context, creating a cleaner architecture.

## Acceptance Criteria

1. A new streaming service module is created that encapsulates all EventSource/SSE connection logic
2. The service handles SSE connection lifecycle: connecting, receiving messages, closing, and error handling
3. The service provides a clean API with callbacks for message chunks, completion, and errors
4. The service manages connection cleanup and abort functionality
5. The service is independent of React and can be used from any part of the application
6. All SSE-specific implementation details are hidden behind the service interface
7. The service properly handles the [DONE] signal to close connections
8. Error handling is comprehensive and provides clear error messages

### Current SSE Implementation Details

[Source: src/app/features/ai-assistant/utils/ai.ts, lines 209-289]

**Existing Function to Refactor**:

```typescript
export function generateResponseFromMessageSSE({
  message,
  context,
  spec,
  onChunk,
  onError,
  onComplete,
}: GenerateResponseSSEParams & GenerateResponseSSECallbacks): SSEAbortFunction;
```

**Current Implementation Patterns to Preserve**:

1. **fetchEventSource Configuration** (lines 221-273):

   - POST method with JSON body
   - Content-Type: application/json header
   - AbortController.signal for cancellation
   - `openWhenHidden: false` to disable auto-retry

2. **onopen Handler** (lines 233-241):

   - Check `response.ok` for HTTP errors
   - Throw error with response text for non-200 status
   - Error format: `HTTP ${status}: ${statusText}`

3. **onmessage Handler** (lines 243-254):

   - Check for `[DONE]` signal
   - Set `isDone = true` before calling `onComplete`
   - Call `abortController.abort()` after completion
   - Otherwise call `onChunk(data)` with text chunk

4. **onerror Handler** (lines 256-270):

   - Check `isDone` flag to skip error handling after success
   - Throw error to stop fetchEventSource retry mechanism
   - Call `abortController.abort()`
   - Extract error message from Error instance or use default
   - Call `onError` callback with Error object

5. **Catch Block** (lines 274-283):

   - Ignore AbortError (expected when aborting)
   - Ignore errors after `isDone = true`
   - Log initialization errors
   - Call `onError` with Error object

6. **Return Abort Function** (lines 286-288):
   - Returns cleanup function that calls `abortController.abort()`

**Current API Endpoint**: `http://localhost:3000/api/generate-response` (line 221)

- NOTE: This is localhost development endpoint
- Production endpoint from REST API spec: `https://pwai.vercel.app/api/generate-response`

### Streaming Service Architecture Design

[Source: Architecture - Frontend Architecture, Coding Standards]

**Service Module Pattern**:

```typescript
// streaming-service.ts structure
export type StreamingServiceParams = {
  endpoint: string;
  message?: string;
  context?: Message[];
  spec?: object;
};

export type StreamingServiceCallbacks = {
  onChunk: (chunk: string) => void;
  onError?: (error: Error) => void;
  onComplete?: () => void;
};

export type StreamAbortFunction = () => void;

/**
 * Streaming service for SSE-based response generation.
 * Framework-agnostic, reusable service module.
 */
export function createStreamingService(): {
  startStream: (
    params: StreamingServiceParams,
    callbacks: StreamingServiceCallbacks
  ) => StreamAbortFunction;
};
```

**Design Principles** [Source: Architecture - Coding Standards, Frontend Architecture]:

1. **Framework Agnostic**: No React dependencies, pure TypeScript
2. **Single Responsibility**: Only handles SSE connection logic
3. **Dependency Injection**: Accept endpoint as parameter for flexibility
4. **Callback Pattern**: Follow functional programming patterns
5. **Error First**: Comprehensive error handling built-in
6. **Type Safe**: Full TypeScript types with strict mode
